# Equipment Monitoring System

API системы мониторинга оборудования на FastAPI.

Приложение позволяет управлять оборудованием, сохранять показания
температуры и давления, получать историю измерений и статистику состояний.

- Создание, просмотр, изменение и удаление оборудования.
- Поиск оборудования по названию и фильтрация по состоянию.
- Добавление измерений и получение последнего показания.
- Получение истории измерений за выбранный период.
- Настройка температурных порогов для каждого устройства.
- Кэширование последних измерений и статистики в Redis.

Состояние оборудования определяется по последней температуре:

- `UNKNOWN` — измерений нет.
- `NORMAL` — температура не превышает порог предупреждения.
- `WARNING` — температура выше порога предупреждения, но не выше критического.
- `CRITICAL` — температура выше критического порога.

Пороги по умолчанию: 70 и 90 °C.

## Технологии

Python 3.13, FastAPI, SQLAlchemy, PostgreSQL, Alembic, Redis,
Docker Compose, pytest, pytest-asyncio, HTTPX.

## Запуск приложения

Для запуска нужен Docker с поддержкой Docker Compose.
На Windows можно использовать Docker Desktop.

Клонировать репозиторий:

```powershell
git clone https://github.com/Ahitame/Equipment_monitoring_system.git
cd Equipment_monitoring_system
```

При первом запуске создать `.env` из шаблона:

```powershell
Copy-Item .env.example .env
```

В `.env` указать параметры контейнерной базы:

```dotenv
POSTGRES_USER=equipment_user
POSTGRES_PASSWORD=changeMe123
POSTGRES_DB=equipment_monitoring
CACHE_TTL=60
```

`POSTGRES_PASSWORD` следует заменить своим паролем. Используйте латинские буквы и цифры.

 `.env.example` содержит пример настроек.

Собрать образ приложения и запустить сервисы:

```powershell
docker compose up -d --build
```

Compose запускает FastAPI, PostgreSQL и Redis.
Миграции Alembic применяются автоматически перед запуском FastAPI.

Документация API: http://127.0.0.1:8000/docs

Проверка состояния сервисов:

```powershell
docker compose ps
```

Данные PostgreSQL сохраняются в томе `postgres_data`.
База внутри Docker создаётся отдельно от PostgreSQL, установленного на компьютере

## Настройки подключения

В контейнер приложения Compose передаёт адреса сервисов `postgres` и `redis`.

Переменные `DATABASE_URL` и `REDIS_URL` из `.env.example` предназначены
для запуска Python вне Docker. Для такого запуска требуется отдельно
подготовить локальную базу и указать её данные

`CACHE_TTL` задаёт время хранения кэша в секундах

## Кэширование

В Redis сохраняются:

- `equipment:statistics` — сводная статистика оборудования.
- `equipment:{equipment_id}:latest` — последнее измерение устройства.

При отсутствии кэша данные читаются из PostgreSQL и сохраняются в Redis с TTL.

После успешного изменения данных связанные записи кэша удаляются
При ошибках Redis приложение продолжает работать с PostgreSQL

## Запуск тестов

Для тестов нужны Python 3.13 и работающий Docker.

Установить зависимости:

```powershell
python -m pip install -r requirements-dev.txt
```

Запустить отдельные тестовые PostgreSQL и Redis:

```powershell
docker compose -p equipment-tests -f compose.test.yaml up -d --wait
```

Тестовые сервисы доступны по адресам:

- PostgreSQL: `127.0.0.1:5433`, база `equipment_test`.
- Redis: `127.0.0.1:6380`.

Таблицы тестовой базы и тестовый кэш сбрасываются перед каждым тестом API.

Запустить весь набор:

```powershell
python -m pytest tests -v
```

Основной контейнер FastAPI запускать для тестов не требуется

Проверяются:

- Работа с оборудованием: создание, получение, изменение и удаление.
- Определение состояния при разных температурах и порогах.
- Отклонение неверных порогов без изменения сохранённых данных.
- Актуальность кэша последнего измерения.
- Актуальность кэша статистики после изменения данных.
- Работа API при ошибках подключения к Redis.


Остановить тестовые сервисы:

```powershell
docker compose -p equipment-tests -f compose.test.yaml stop
```
